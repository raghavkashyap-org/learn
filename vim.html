01 / Introduction

What is Vim?

Vim (Vi IMproved) is a highly configurable, modal text editor built for efficiency. Created by Bram Moolenaar in 1991 as an improvement upon Bill Joy's vi (1976), Vim runs everywhere — from remote SSH servers to modern IDEs via plugins.

Vim's core insight is radical: editing and typing are different activities that deserve different keyboard behaviors. Most time spent "editing" is actually navigation, selection, deletion, and transformation — not raw typing. Vim optimizes for this reality.

⚠ The Famous First Obstacle

To quit Vim, press :q then Enter. If you've made changes, use :q! to discard them, or :wq to save and quit. You're not alone — this trips up everyone.

02 / Philosophy

The Vim Philosophy

Understanding Vim's philosophy is more important than memorizing commands. Everything in Vim derives from one core principle:

The Vim Principle
Editing is not the same as typing.
Optimize them separately.

Typing vs Editing

In a traditional editor like VS Code or Notepad, your keyboard always types characters. To do anything else (move, select, delete), you need modifier keys: Ctrl+C, Ctrl+Arrow, Shift+End.

In Vim, most of your time is in Normal Mode — where every key is a command. You switch to Insert Mode only when you need to type text, then immediately return. This separation unlocks keyboard efficiency that modifiers can never match.

The Composable Language

Vim commands compose like a language. Learn 10 operators and 20 motions, and you get 200 combinations — rather than memorizing 200 separate shortcuts.

" Traditional editor: 5 separate shortcuts to memorize
Ctrl+Delete  → delete word right
Ctrl+Back    → delete word left  
Home         → go to line start
Ctrl+Shift+K → delete line
Ctrl+D       → duplicate line

" Vim: compose d (delete) + motion
dw   → delete word
db   → delete backward word
d0   → delete to line start
dd   → delete line
yy   → copy line (swap d→y)

10 / Replace Mode

Replace Mode Intermediate

Enter with R. Typing overwrites existing characters rather than inserting. Press Esc to return to Normal.

For a single-character replacement, use r in Normal mode — it replaces one character and returns to Normal automatically, which is far more common.

Before: hello world
         ^ cursor at 'w'

Press R, type "Vim":
After:  hello Vimld
⚠ Backspace in Replace Mode

Pressing Backspace in Replace Mode restores the original character that was overwritten — it doesn't just delete a character. This is unique to Replace Mode.

KeyAction
REnter Replace Mode (multi-char overwrite)
rReplace single char, auto-return to Normal
gRVirtual Replace Mode (replaces screen columns, not bytes)
grVirtual replace single char
11 / Select Mode

Select Mode Intermediate

Select Mode behaves like GUI editor selection: selected text is immediately replaced when you start typing. This is different from Visual Mode, where typing runs commands.

KeyAction
ghEnter Character Select Mode
gHEnter Line Select Mode
g Ctrl+hEnter Block Select Mode
Ctrl+gToggle between Visual and Select modes
ℹ When Select Mode Is Used

Select Mode is primarily used by snippet plugins (like UltiSnips) to highlight placeholders. When a snippet fires, you're placed in Select Mode so typing directly replaces the placeholder text.

12 / Ex Mode

Ex Mode Advanced

Enter with Q (capital). Ex Mode is a line-oriented command shell from Vim's heritage. You type commands line by line. Exit with visual or vi.

Enter Ex Mode → press Q

Entering Ex mode.  Type "visual" to go to Normal mode.
:1,5delete        " delete lines 1-5
:%substitute/a/b/g
:print             " print current line
:visual            " return to Normal
⚠ Accidental Ex Mode

Pressing Q accidentally puts you in Ex Mode. Type visual and press Enter to get back out. This confuses many beginners.

Why Ex Mode Still Matters

Most powerful Command-Line Mode commands (:s, :g, :v, :d) are actually Ex commands running under the hood. Ex Mode just exposes them in a line-by-line batch interface.

CommandAction
:g/pattern/dDelete all lines matching pattern
:g/pattern/pPrint all lines matching pattern
:v/pattern/dDelete all lines NOT matching pattern
:g/^$/dDelete all blank lines
:g/pattern/norm ddRun Normal command on matched lines

The Dot Command — Repeat Last Change

The . command repeats the last change. It's the most powerful single-key command in Vim. The key insight: design your edits to be repeatable.

n.             " Next match, repeat delete

19 / Registers

Registers — Multiple Clipboards Advanced

Vim doesn't have one clipboard — it has dozens. Every yank, delete, and change is stored in a register. Think of registers as named memory slots.

Using Registers

" Formula: " + register name + action

"ayy     " Yank line into register a
"ap      " Paste from register a
"Ayy     " APPEND line to register a (uppercase = append)
"bdd     " Delete line into register b
"+y      " Yank to system clipboard
"+p      " Paste from system clipboard
"_dd     " Delete to black hole (no clipboard pollution)

Register Types

RegisterNamePurpose
""UnnamedDefault register — all y/d/c go here
"0Yank registerOnly set by yank (y), never by delete
"1–"9Delete history"1 = most recent multi-line delete, shifts like a stack
"a–"zNamedManual storage; never auto-overwritten
"A–"ZNamed (append)Uppercase appends to lowercase register
"-Small deleteDeletions less than one line (x, dw…)
"+System clipboardOS clipboard (Ctrl+C / Ctrl+V)
"*Primary (X11)Mouse selection clipboard on Linux
".Last insertRead-only: last inserted text
"%FilenameRead-only: current file name
":Last commandRead-only: last : command run

"/Last searchRead-only: last search pattern

The "0 Register Trick

💡 Key Insight

If you yank text, then delete something, your yank is overwritten in the unnamed register. Use "0p to paste your original yank regardless of subsequent deletions.

Viewing Registers

:reg        " Show all registers
:reg a b    " Show registers a and b only

Pasting from Register in Insert Mode

" While in Insert Mode:
Ctrl+r a         " Paste register a
Ctrl+r +         " Paste system clipboard
Ctrl+r 0         " Paste last yanked text
Ctrl+r %         " Paste current filename
Ctrl+r Ctrl+o a  " Paste with correct indentation
20 / Macros

Macros — Recorded Automation Advanced

Macros record a sequence of Normal Mode actions into a register and replay them. Perfect for repetitive structural edits.

Basic Workflow

qa              " Start recording macro into register 'a'
"   ... do your edits ...
q               " Stop recording
@a              " Replay macro once
@@              " Replay last used macro
10@a            " Replay 10 times
:%normal @a     " Run macro on every line in file

Practical Macro Example

--- Transform list to JSON array ---
Before:
apple
banana
orange

Goal:
"apple",
"banana",
"orange",

qa           " start macro
I"<Esc>      " insert " at start
A",<Esc>     " append ", at end
j            " move down
q            " stop macro
2@a          " run on next 2 lines

Editing Macros

Macros are stored in registers, so you can edit them as text:

:let @a = 'Ihello<Esc>j'  " Set macro directly

" Or: paste macro, edit it, yank back
"ap    " paste macro a as text
" ... edit the text ...
"ayy   " yank it back into register a
💡 Macro Design Rule

Design macros to be self-positioning. End each macro by moving to the start position for the next iteration (usually j for next line). This lets you run them N times without error.

22 / Search & Replace

Search & Replace — Deep Dive Intermediate

Search Options

set hlsearch    " Highlight all matches
set incsearch   " Jump as you type (incremental)
set ignorecase  " Case-insensitive
set smartcase   " Case-sensitive if uppercase used

:noh            " Clear search highlight temporarily

Advanced Substitution

" Basic
:%s/foo/bar/g           " Replace all foo with bar

" With confirmation
:%s/foo/bar/gc          " Confirm each: y/n/a/q/l/^E/^Y

" Empty replacement = delete
:%s/\s\+$//            " Remove trailing whitespace

" With capture groups
:%s/\v(\w+) (\w+)/\2 \1/  " Swap two words

" Using & (entire match)
:%s/error/[&]/g        " Wrap "error" in brackets

" Case modifiers

25 / Undo System

Undo — Branching History Advanced

Vim's undo system is a tree, not a linear stack. When you undo and then make a new edit, the previous future is preserved as a branch — you can still navigate to it.

u           " Undo last change
Ctrl+r      " Redo
5u          " Undo 5 changes
:undolist   " Show undo tree branches
:undo 3     " Jump to undo state #3
:earlier 5m " Go to file state 5 minutes ago
:later 30s  " Go forward 30 seconds in history

" Persistent undo (survives restarts)
set undofile
set undodir=~/.vim/undo
💡 Time-Based Undo

:earlier 5m and :later 1h are unique to Vim — you can travel back to the exact state of your file at any point in time, even if you made thousands of changes. Enable undofile to make this survive restarts.

29 / Errors

Vim Error Reference Core

Vim errors follow the format E{number}: {message}. Here are the most common ones with explanations and fixes.

File & Save Errors

E37: No write since last change (add ! to override)
You tried to quit or switch buffers with unsaved changes. Vim is protecting your work.
:wq to save+quit, :q! to discard, :w to just save
E13: File exists (add ! to override)
Happens with :w newfile when the file already exists. Vim won't silently overwrite.
:w! filename to force overwrite
E45: 'readonly' option is set (add ! to override)
The file is marked read-only (opened with :view or the file system flag is set).
:w! to force, or :set noreadonly then :w
E212: Can't open file for writing
File system permission denied. The user doesn't have write permission on the file.
:w !sudo tee % to write with sudo
E514: Write error in swap file
Disk full or permissions issue writing the swap file.
Free disk space; :set noswapfile to disable swap

Navigation Errors

E486: Pattern not found: {pattern}
The search pattern doesn't exist in the file. Search wrapped around without finding a match.
Check spelling; :set ignorecase for case-insensitive
E385: Search hit BOTTOM, continuing at TOP
Normal info — search wrapped from bottom to top of file. Not an error.
Set :set nowrapscan to disable wrap-around
E20: Mark not set
Tried to jump to a mark ('a) that hasn't been set.
Set mark first: ma then jump with 'a

Buffer Errors

E162: No write since last change for buffer {N}
Like E37 but for a specific buffer number when doing :qa.
:wa to save all, or :qa! to discard all
E516: No buffers were deleted
:bd failed because the buffer has unsaved changes.
:bd! to force delete (lose changes)

Macro & Register Errors

E21: Cannot make changes, 'modifiable' is off
The buffer is set as non-modifiable (common in help files, quickfix windows).
:set modifiable — but usually leave special buffers alone
E29: No inserted text yet
Tried to use the ". register (last inserted text) before inserting anything.
Enter Insert Mode and type something first

Command Errors

E492: Not an editor command: {cmd}
Typed an unknown command in Command-Line mode. Typo or missing plugin.
Check spelling; install plugin if it's a plugin command
E488: Trailing characters
Extra characters after a command that doesn't accept arguments.
Remove extra text after command
E553: No more items
Tried to go beyond the end of a list (quickfix, location list).
Already at last item in the list
E17: "{file}" is a directory
Tried to :e or :w a directory path instead of a file.
Use :Explore or a file explorer to navigate into the directory
E303: Unable to open swap file for "..." recovery may be impossible
Swap file directory doesn't exist or isn't writable.
Create ~/.vim/swap/ directory; set swapdir correctly
E325: ATTENTION — Found a swap file
A previous Vim session crashed or is still running with this file. Vim found an existing swap file.
Press R to recover, D to delete swap, or O to open read-only
E701: Invalid argument: {arg}
Wrong argument type or value passed to a command or option.
Check :help for the correct syntax of the command
30 / Shell Integration

Shell Integration — ! vs :terminal Advanced

Vim has two ways to interact with the shell. They serve different purposes.

The ! (Filter/Execute) Method

! runs a shell command in a subprocess. The command runs briefly, shows output, and returns you to Vim.

:!ls              " Run ls, see output, press Enter to return
:!git status      " Run git status
:!python %        " Run current file

" Filter buffer text THROUGH a command
:r !date          " INSERT output of date into buffer
:.!wc -w          " Replace current line with word count
:%!python -m json.tool  " Format buffer as JSON
!ip sort          " Sort paragraph (Normal mode)
!!sort            " Filter current line through sort

The :terminal Method

:terminal opens a persistent interactive shell inside a Vim buffer. It stays open, you can scroll through history, copy output, and use it alongside your files.

:terminal         " Persistent embedded shell
:vert terminal    " In vertical split

Side-by-Side Comparison

Feature:! command:terminal
InteractionOne-shot, no interactivityFull interactive shell
Output staysNo (press Enter to dismiss)Yes, scrollable buffer
Copy outputNoYes (Terminal-Normal mode)
Filter buffer textYes (:r !, :%!, !motion)No
REPLs / long jobsNoYes
Run test suiteWorks but output gone fastBetter, stays visible
Best forQuick one-liners, text filteringGit, builds, REPLs, SSH
